# /study Command

공식문서와 이 저장소의 실제 코드를 대조해 학습한다. 소스 수정 금지.

문서만 요약하면 블로그 글과 같다. **대조가 이 커맨드의 존재 이유다.**
공식 설명이 전제하는 구조와 이 저장소의 실제가 어긋나는 지점, 거기가 배울 곳이다.

## 사용법

```
/study <주제>
/study <파일경로>
/study <주제> --note
```

## 사전 준비 (최초 1회)

공식 레퍼런스 캐시가 없으면 만든다. 없어도 동작하지만 근거가 약해진다.
받을 저장소 목록과 캐시 위치는 project.json 의 `learning.sample_repos` / `learning.cache_dir` 이다.
설정이 비어 있으면 이 단계를 건너뛰고, 근거가 문서뿐이라는 사실을 보고에 남긴다.

```bash
CACHE="<learning.cache_dir>"
mkdir -p "$CACHE" && cd "$CACHE"
for url in <learning.sample_repos>; do
  name=$(basename "$url" .git)
  git clone --depth 1 --filter=blob:none --sparse "$url"
  (cd "$name" && git sparse-checkout set --no-cone '/*' '!/*/' '**/*.md' <learning.source_globs 를 따옴표로 하나씩>)
done
```

희소 체크아웃이 필수다. 안 걸면 이미지와 바이너리까지 받아 수백 MB 가 되고,
소스만 받으면 수십 MB 로 끝나면서 grep 대상은 그대로 남는다.

## 동작 순서

1. **tutor 에이전트를 호출한다.**
   이 커맨드는 해당 에이전트 호출을 명시적으로 요청하는 것이다 (Agent tool 사용 승인).
   프롬프트에 학습 주제를 그대로 전달한다.
2. 에이전트가 공식문서 확인 -> 저장소 사용처 grep -> 대조 보고를 수행한다.
3. 에이전트 보고를 터미널에 그대로 옮긴다. 요약하지 않는다.

## 옵션

`--note` : 학습 노트를 파일로 남긴다. 에이전트는 쓰기 권한이 없으므로 **메인 루프가 직접 쓴다.**

1. `mkdir -p <docs.study_dir>` (폴더가 없을 수 있다)
2. 에이전트 보고를 `<docs.study_dir>/<YYYYMMDD>_<주제>.md` 로 저장
3. `docs.vault_prefix` 가 설정돼 있으면 연결된 노트 앱 도구로 `<docs.vault_prefix>/<같은 경로>` 에 동기화
4. `docs.study_dir` 이 비어 있으면 파일을 만들지 않고 그 사실을 보고한다 (임의 경로에 쓰지 않는다)

`--note` 없으면 터미널 출력만 하고 파일을 만들지 않는다.

붙이는 기준: 나중에 다시 볼 주제(학습 로드맵 항목, 의심 지점이 나온 주제, 리포트가 긴 주제)에는 붙인다.
단발 확인에는 안 붙인다. 같은 주제를 다시 돌리면 날짜가 달라 새 파일이 생긴다 - 덮어쓰지 않는다.
저장소가 바뀌면 grep 수치도 바뀌므로 시점별 기록이 추세가 된다.

## 주의: 에이전트 정의 캐시

`.claude/agents/tutor/AGENT.md` 를 수정해도 **실행 중인 세션에는 반영되지 않는다.**
에이전트 정의는 세션 시작 시 한 번 읽힌다. 수정했으면 세션을 새로 시작해야 적용된다.
(실측으로 확인한 동작이다. 파일에는 있는 절을 에이전트가 못 받는 상황이 나온다.)

## 규칙

- 도메인 문서는 건드리지 않는다. 학습 노트는 `docs.study_dir` 에만 쌓는다.
- 소스 파일 수정 금지. 공부 도구다.
- 주제가 모호하면 되묻지 말고 가장 흔한 해석으로 진행하고 그 사실을 밝힌다.
