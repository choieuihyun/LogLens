# documenter: 공사가 끝날 때마다 건물 도면집에 바뀐 곳을 적어 넣는 기록 담당

## 무엇을 하나

코드가 바뀐 뒤, 그 부분을 설명하는 도메인 문서(DOMAIN.md)에 변경 이력과 핵심 모듈을 갱신한다.
문서가 없으면 뼈대로 새로 만들되, 코드로 확인한 것만 채우고 나머지는 비워 둔다.
설정돼 있으면 같은 내용을 노트 앱에도 올린다. 사소한 변경이면 "문서화 불필요" 로 끝낸다.

## 언제 불리나

| 커맨드 | 단계 |
|---|---|
| `/feature` | 8단계 문서화 (DOCUMENTING). 신규 기능은 항상 해당 |
| `/fix` | 성공 종료 후 변경 규모에 따라 (클래스 추가/삭제, 주요 로직 변경일 때만) |

## 못 하는 것

- 코드 파일 수정: 지시로 막음, 도구로는 안 막힘 (Write 가 있다). 문서 담당이 코드를 고치면 무엇이 바뀌었는지 기록할 기준이 흐려진다
- 명령 실행과 검색(Bash, Grep, Glob 없음): 도메인은 오케스트레이터가 계산해 넘긴다. 직접 계산하지 않는다
- git 명령: 저장소 상태는 오케스트레이터만 바꾼다
- 노트 앱 쓰기: 그 도구를 붙이기 전까지는 로컬 파일만 쓴다 (붙일지는 /setup 이 이 에이전트 차례에 묻는다)

## 넘겨주는 것

갱신하거나 새로 만든 문서 경로, 추가한 변경 이력, 비워 둔 절, 노트 앱 동기화 여부를 보고한다.
오케스트레이터가 종료 보고에 싣고, 이렇게 쌓인 DOMAIN.md 는 다음 작업에서
explorer, planner, implementer, verifier 등이 작업 전에 읽는 지식이 된다.

## 여기에 넣으면 좋아지는 것

- 도메인 문서 위치: 모바일은 `docs/features/`, 웹은 `docs/pages/`, 서버는 `docs/services/` 처럼 정해 주면 거기에 쌓는다
- 노트 앱 연결: 팀이 노트 앱에서 문서를 본다면 그 경로 접두사와 쓰기 도구를 알려 주면 로컬과 같은 내용을 올린다
- 문서화 기준 조정: 예를 들어 서버는 "엔드포인트 추가는 늘 기록", 웹은 "스타일만 바뀐 변경은 기록하지 않음" 같은 행동 규칙
- 도메인별 첫 지식: 불변식, 흔한 함정은 이 에이전트가 지어내지 않고 비워 두므로, 사용자가 DOMAIN.md 에 먼저 적어 두면 갱신이 그 위에 쌓인다

## 질문

| # | 사용자에게 할 질문 | 스캔으로 추측 | 저장 위치 | 안 채우면 |
|---|---|---|---|---|
| 1 | 도메인(기능 단위) 설명 문서를 어느 폴더에 모을까요? | `docs/` 아래 기능 이름별 하위 폴더, 기존 `DOMAIN.md` 위치 | `docs.domain_map` | 도메인 문서를 갱신하지 않는다. 다른 문서 키도 비었으면 "문서화 대상 없음" 으로 끝낸다 |
| 2 | 문서를 노트 앱에도 올리나요? 올린다면 볼트 안의 경로 접두사는 무엇인가요? | 불가 | `docs.vault_prefix` | 동기화를 건너뛰고 로컬 문서만 남긴다 |
| 3 | 문서로 남길 변경과 남기지 않을 변경에 이 프로젝트만의 기준이 있나요? | 불가 | `.claude/project/agents/documenter.md` | 뼈대의 트리거 여섯 가지만 쓴다 |
| 4 | 주요 기능마다 용어, 깨지면 안 되는 규칙, 자주 터지는 곳을 알려 주시겠어요? | 불가 (코드만 보고 쓰면 추측이 사실로 읽힌다) | `DOMAIN.md` | 새 문서의 용어, 불변식, 위험 지점, 흔한 함정, 외부 의존 절이 빈 채로 남는다 |
