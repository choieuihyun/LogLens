# triage: 테스트가 넘어진 현장에서 원인 딱지만 붙이는 사고 조사관

## 무엇을 하나

자동 동작 재생(E2E)이 실패했을 때 원인을 네 가지 중 하나로 가른다.
진짜 버그, 가끔 늦어서 생긴 실패, 테스트 시나리오 자체의 오류, 실행 환경 문제.
환경과 시나리오와 타이밍을 먼저 의심하고 모두 아닐 때만 진짜 버그라고 판정한다. 헛된 코드 수정을 막기 위해서다.

## 언제 불리나

| 커맨드 | 단계 |
|---|---|
| `/fix` | 3.5단계 런타임 게이트에서 재생이 실패했을 때 |
| `/feature` | 7.5단계 런타임 게이트에서 재생이 실패했을 때 |

## 못 하는 것

- 파일을 쓰지 못한다 (Write, Edit 없음). 조사관이 현장을 고치면 원인이 지워진다
- 코드 검색 도구가 없다 (Grep, Glob 없음). 재생 결과, 실패 화면, 리포트, 로그만 근거로 삼는다
- Bash 는 로그 읽기 전용이다. 재생 재실행, 빌드, 배포는 문서 규칙으로 막혀 있다. 다시 돌릴지는 오케스트레이터가 정한다

## 넘겨주는 것

`triage.json`: 분류, 신뢰도, 근거, 다음 행동, 의심 파일. 오케스트레이터가 이것으로 갈린다.
진짜 버그면 의심 파일을 들고 implementer 재호출, 간헐 실패면 재생만 다시(2회 초과면 사람 판단),
시나리오 오류면 시나리오 수정, 환경 문제면 바로 사람에게 넘긴다. 신뢰도가 LOW 여도 사람에게 넘긴다.

## 여기에 넣으면 좋아지는 것

- 원래 가끔 실패하는 시나리오를 알려 주면 진짜 버그로 오판해 코드를 고치는 루프를 덜 돈다
- 환경 실패의 얼굴을 알려 주면 빨리 사람에게 넘긴다. 모바일이면 권한 팝업이나 기기 잠금,
  웹이면 미리보기 서버 포트 충돌이나 동의 배너, 서버면 DB 컨테이너 미기동이나 스키마 미적용
- 어댑터에 로그 명령이 없는 스택(웹, 서버)은 대신 볼 로그 위치를 알려 주면 근거가 하나 늘어 신뢰도가 오른다
- 이 프로젝트 로그에서 실패를 뜻하는 표현을 알려 주면 기본 세 단어 밖의 실패도 잡는다
