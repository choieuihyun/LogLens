# builder: 공사가 끝날 때마다 도면대로 지어졌는지 기계에 넣어 보는 검수 기사

## 무엇을 하나

프로젝트의 빌드 명령을 돌려 코드가 컴파일되는지 확인한다. 성공 여부는 종료코드로만 정한다.
실패하면 에러 로그에서 어느 파일 몇 번째 줄인지 뽑고, 그 위치를 얼마나 믿을 수 있는지(HIGH, MEDIUM, LOW) 매긴다.
에러가 있어도 직접 고치지 않는다. 명령을 추측해서 돌리지도 않는다. 설정에 적힌 명령만 쓴다.

## 언제 불리나

| 커맨드 | 단계 |
|---|---|
| `/fix` | 0단계 인테이크 모드 B (`--build`). 고칠 에러를 먼저 확보한다. 성공하면 대상 없음으로 끝난다 |
| `/fix` | 3단계 빌드 (BUILDING). 수정할 때마다 |
| `/feature` | 7단계 검증 + 빌드. verifier 와 병렬 |

## 못 하는 것

- 파일 수정 (Edit, Write 없음): 검수 기사가 고치면 "빌드가 됐다" 가 무엇을 증명하는지 흐려진다
- 결과를 파일로 저장하지 못한다: 같은 이유로 쓰기 권한이 없다. 오케스트레이터가 받아 저장한다
- 검색 (Grep, Glob 없음): 위치 추출은 스크립트가 한다
- 빌드 명령 외의 명령, git, 배포와 실행 (규칙): 컴파일만 한다. 올리고 재생하는 것은 런타임 게이트 몫이다

## 넘겨주는 것

빌드 결과 json 하나: 성공 여부, 에러 해시, 에러 파일, 위치 신뢰도, 한 줄 요약, 핵심 로그 최대 10줄.
오케스트레이터가 같은 에러 해시가 3번 나오면 멈추고, 신뢰도로 다음 단계를 고른다.
LOW 이거나 HIGH 인데 허가 목록 밖이면 explorer 를 다시 부르고(LOW 두 번 연속이면 사람 확인), MEDIUM 이거나 HIGH 면서 허가 목록 안이면 implementer 에게 에러를 넘긴다.

## 여기에 넣으면 좋아지는 것

- 빌드 명령을 정확히 주면 무엇을 빌드했는지 분명해진다. 예: 모바일은 디버그 변형 하나만, 웹은 타입 검사 포함 빌드, 서버는 컴파일과 린트
- 기기마다 다른 도구 경로(SDK, 런타임 버전 관리자)를 후보로 주면 다른 컴퓨터에서도 도구를 찾는다
- 기본 형식 밖의 에러 형식(템플릿 파일, 리소스 처리 단계)을 알려 주면 위치 신뢰도가 LOW 에서 HIGH 로 오른다
- 빌드가 오래 걸리거나 캐시를 먼저 지워야 하는 사정을 알려 주면 보고에 그 맥락을 붙인다

## 질문

| # | 사용자에게 할 질문 | 스캔으로 추측 | 저장 위치 | 안 채우면 |
|---|---|---|---|---|
| 1 | 어떤 스택인가. 준비된 어댑터 중 맞는 것이 있는가 | 빌드 파일 종류 (package.json, 빌드 스크립트, pyproject) | `adapter` | `adapter_inline` 도 없으면 설정 로드 실패로 빌드를 시도하지 않고 실패로 보고한다 |
| 2 | 맞는 어댑터가 없으면 빌드 명령을 직접 적는다. 파일:줄 같은 흔한 형식 밖의 빌드 에러 형식이 있으면 함께 적는다 (맞는 어댑터가 있고 에러 형식만 더하면 `adapter_override.error_patterns`, 어댑터가 없으면 `adapter_inline` 에 명령까지 통째로) | package.json scripts, 실패한 빌드 로그 한 번 | `adapter_override` 또는 `adapter_inline` | `adapter` 를 쓴다. 에러 형식을 안 적으면 기본 세 형식만 읽어, 형식이 다를 때 매번 LOW 에 "빌드 에러 형식 미등록" 이 붙고 `/fix` 는 explorer 재실행을 돌다 두 번 연속이면 사람 확인으로 간다 |
| 3 | 빌드 명령의 빈칸에 넣을 값은 (빌드 대상 이름 등) | package.json scripts, 빌드 스크립트의 태스크 목록 | `vars` | 빈칸이 남았다고 알리고 빌드를 시도하지 않는다 |
| 4 | 빌드 전에 켜 둬야 하는 환경변수가 있는가 | CI 설정 파일의 env 항목 | `env` | 내보내지 않는다. 도구 미탐지나 버전 불일치로 실패할 수 있다 |
| 5 | 컴퓨터마다 경로가 다른 환경변수가 있는가 (후보 경로 여러 개) | 흔한 설치 경로의 존재 여부 | `env_candidates` | 생략된다. 다른 기기에서 도구를 못 찾을 수 있다 |
| 6 | 빌드에 대해 따로 알아 둘 사정이 있는가 (오래 걸림, 무시해도 되는 경고) | 불가 | `.claude/project/agents/builder.md` | 종료코드만 보고 판단한다 |
