# explorer: 공사 전에 어디를 고쳐야 하는지 지도를 그려 오는 정찰병

## 무엇을 하나

버그 설명이나 에러, 기능 계획을 받아 관련 코드를 찾아 읽고 "이 파일들을 고치면 된다" 는 범위를 제안한다.
고칠 곳이 여러 사람이 같이 쓰는 위험한 곳(동기화, 상태 전파, 동시성, 저장소, 목록 갱신)에 닿는지도 표시한다.
직접 고치지는 않는다. 이 제안으로 뒤의 수정 담당이 손댈 수 있는 파일 목록이 정해진다.

## 언제 불리나

| 커맨드 | 단계 |
|---|---|
| `/fix` | 1단계 탐색 (EXPLORING). 빌드 에러 위치를 모르거나(LOW) 허가 목록 밖에서 나면 다시 불린다 |
| `/feature` | 5단계 탐색. 승인된 계획을 배선할 기존 파일만 확정한다 (새 파일은 planner 몫) |

## 못 하는 것

- 파일 수정 (Edit, Write 없음): 찾는 쪽이 고치면 허가 범위를 스스로 넓힐 수 있다. 제안과 수정을 물리적으로 나눈다
- 결과를 파일로 저장하지 못한다: 같은 이유로 쓰기 권한이 없다. 오케스트레이터가 받아 저장한다
- git 명령과 저장소 전체 훑기 (Bash 는 있지만 규칙으로 막는다): 필요한 곳만 읽어야 컨텍스트가 안 부푼다
- 빌드 설정 파일 읽기 (의존성 변경 맥락이 없을 때, 규칙): 대부분의 수정과 무관하고 양이 많다

## 넘겨주는 것

수정 제안 json 하나: 고칠 파일, 참고만 할 파일, 무시할 파일, 위험 축(SYNC, EVENT, THREAD, DB, LIST), 위험도(HIGH, MEDIUM, LOW), 한 줄 요약.
오케스트레이터가 금지 글롭으로 거른 뒤 허가 목록으로 확정하고, 위험도가 HIGH 면 사람 확인(Human Gate)을 부른다.
위험 축은 implementer 가 어떤 수정 규칙을 적용할지 고르는 데 쓴다.

## 여기에 넣으면 좋아지는 것

- 위험 축 글롭을 주면 축 판정이 재량이 아니라 규칙이 된다. 예: 모바일은 로컬 DB 스키마 폴더를 DB 로, 웹은 전역 store 폴더를 EVENT 로, 서버는 메시지 큐 소비자 폴더를 EVENT 로
- 건드리면 파급이 큰 공유 파일(공통 네트워크 계층, 인증 미들웨어, 디자인 토큰 파일)을 알려 주면 최소 MEDIUM 으로 올려 사람이 한 번 더 본다
- 먼저 볼 곳과 피할 곳(생성 코드 폴더, 벤더 복사본, 빌드 산출물)을 알려 주면 헛탐색이 준다
- 이 프로젝트에서 "빌드 설정 파일" 로 칠 목록을 알려 주면 읽기 금지 규칙이 정확히 걸린다
- 도메인 문서가 있으면 용어와 불변식을 알고 탐색해 엉뚱한 파일을 덜 고른다

## 질문

| # | 사용자에게 할 질문 | 스캔으로 추측 | 저장 위치 | 안 채우면 |
|---|---|---|---|---|
| 1 | 다섯 위험 축마다 해당하는 폴더는 어디인가. SYNC(여러 기기, 세션, 인스턴스에 같은 상태), EVENT(이벤트 버스, 전역 store, 메시지 큐), THREAD(백그라운드, 비동기 작업), DB(영속 저장소, 스키마), LIST(부분 갱신, 페이지 조회 목록). 없는 축은 비운다 | 폴더 이름의 sync, store, queue, worker, migration, 의존성 목록의 상태 관리와 큐 라이브러리 | `risk_axes` | 축 판정이 매번 explorer 재량이 된다. SYNC, EVENT 를 놓치면 HIGH 로 안 올라가 사람 확인 없이 수정되고, THREAD, DB 를 놓치면 MEDIUM 대신 LOW 가 된다 |
| 2 | 축을 딱 정하긴 어렵지만 건드리면 파급이 큰 공유 파일이 있는가 | 가장 많이 import 되는 파일 | `risk_globs` | 위험 가중이 없다. 공유 파일을 고쳐도 LOW 로 지나갈 수 있고, `/feature` 5단계의 공유 파일 게이트(Human Gate)도 걸리지 않는다 |
| 3 | 탐색할 때 먼저 볼 곳, 피할 곳, 빌드 설정 파일로 칠 목록이 있는가 | 생성 코드와 산출물 폴더, 빌드 스크립트 파일 | `.claude/project/agents/explorer.md` | 매번 심볼 검색부터 시작하고, 빌드 설정 파일의 경계는 explorer 가 짐작한다 |
| 4 | 도메인마다 용어, 지켜야 할 불변식, 흔한 함정을 적은 문서가 있는가 | 불가 | `DOMAIN.md` | 도메인 지식 없이 코드만 보고 판단한다. `docs.domain_map` 이 비어 있으면 경로 자체가 안 잡혀 읽지 않는다 |
