# LogLens 레코드 포맷 — 계약 (v1)

라이브러리(emitter)와 뷰어(parser)를 잇는 **유일한 결합점**이다.
양쪽은 코드 의존이 없다. 이 문서와 `viewer/tests/fixtures/` 가 공동의 진실이다.

---

## 1. 레코드 본문 (body)

```
evt=<EVENT> <key>=<value> <key>=<value> | <free message>
```

- `evt=` 로 시작해야 구조화 레코드로 인정된다. 아니면 **unstructured** 로 강등(버려지지 않음).
- `key=value` 는 공백으로 구분. **값에는 공백·`|`·개행이 없다** (emitter 가 sanitize 책임).
- `| ` 뒤는 자유 메시지. 공백 허용. 없어도 된다.
- 필드가 없어도 되고(`evt=PING`), 메시지만 있어도 된다(`evt=PING | hello`).

### 문법 (EBNF 유사)

```
body    = "evt=" event , { " " , field } , [ " | " , message ] ;
event   = TOKEN ;
field   = key , "=" , value ;
key     = ( ALPHA | "_" ) , { ALNUM | "_" } ;
value   = TOKEN ;                     (* 공백/파이프/개행 불가, 1자 이상 *)
message = { ANY-EXCEPT-NEWLINE } ;
TOKEN   = 1*( any char except SPACE, TAB, CR, LF, "|" ) ;
```

## 2. 태그 = `<PREFIX>_<DOMAIN>`

```
APP_AUTH   APP_NET   APP_FILE_XFER
```

- `PREFIX` 는 프로젝트가 정한다 (`config.json` 의 `prefix`, 기본 `APP`).
- `DOMAIN` 은 **`[A-Z0-9_]+`**. 대문자·숫자·언더스코어.
  > 초안의 `[A-Z]+` 는 `FILE_XFER` / `API2` 같은 흔한 도메인을 거부한다. 넓혔다.
- 뷰어는 `PREFIX` 를 **정규식 이스케이프한 뒤** 패턴에 끼운다.

---

## 3. 줄 접두사 (prefix) — 소스마다 다르다

**초안의 단일 정규식은 틀렸다.** `\d{4}-\d\d-\d\d` 는 연도를 포함하는데, `adb logcat` 의
표준 포맷들은 연도를 찍지 않는다. 그래서 **얇은 접두사 파서 3종 + 공용 body 파서 1개** 구조로 간다.

| 소스 | 예시 | 비고 |
|---|---|---|
| `logcat -v threadtime` | `08-12 11:23:45.678  1234  5678 I APP_AUTH: <body>` | **뷰어 기본**. adb 호출 시 명시적으로 고정 |
| `logcat -v brief` | `I/APP_AUTH( 1234): <body>` | 초안 예시가 이 형태 |
| 파일 싱크 | `2026-08-12 11:23:45.678 I/APP_AUTH: <body>` | 우리가 포맷을 소유하므로 연도 포함 |

접두사에서 뽑는 것: `ts`, `pid`, `tid`, `level`, `tag`. 나머지는 `body` 로 넘긴다.
어느 접두사에도 안 맞으면 → `RAW` 레코드 (원문 보존, 뷰어에 회색으로 표시).

### 레벨
`V D I W E` — 그리고 logcat 이 내는 `F`(fatal), `A`(assert) 도 파서는 받아준다(`E` 로 승격).

## 4. 불변식 (invariants)

### I1. 한 줄 = 한 레코드
개행으로 쪼개지 않는다. 스택트레이스는 `\n` → `\\n` 이스케이프해서 한 줄에 밀어넣거나
필드로 요약(`err=ConnectException:timeout`)한다.

원문(8절)은 큰 본문을 여러 줄로 보내지만 이 불변식을 깨지 않는다. 조각 하나하나가 `evt=` 로
시작하는 온전한 레코드이고, 어느 줄도 다른 줄 없이 파싱된다.

### I2. 4KB 잘림은 **코드포인트 경계**에서
logcat 은 한 줄당 ~4000 바이트 근처에서 자른다. emitter 가 먼저 자르되,
**UTF-8 바이트로 세고 코드포인트 경계에서 끊는다.** 한글은 3바이트/자라서
순진하게 바이트로 자르면 깨진 문자(mojibake)가 나온다. 자른 뒤 `...[cut]` 을 붙인다.

### I3. 파서는 관용적, emitter 는 엄격
파서는 절대 예외를 던지지 않는다.
잘린 줄(필드가 토큰 중간에 끊김, `|` 꼬리 없음)도 들어온다.
파싱 실패 = 예외가 아니라 **`RAW` 로 강등**.

파서가 봐주는 것 (emitter 는 그래도 만들면 안 되는 것):

| 입력 | 파서 동작 | 이유 |
|---|---|---|
| 줄 끝 공백 | `rstrip` 후 파싱 | 공백 한 칸에 레코드 전체를 강등시킬 이유가 없다. **실제로 이 한 칸에 당했다** — 합성 생성기가 필드 뒤에 공백을 남겨서 FILE_XFER 성공률이 0%로 나왔다 |
| `F`/`A` 레벨 | `E` 로 승격 | logcat 이 실제로 낸다 |
| 접두사 3종 혼재 | 각각 인식 | 소스마다 다르다 |

### I4. 빈 값 금지 → 센티널
`k=` 는 문법상 값이 0자라 토큰이 아니다. emitter 는 빈 문자열/`null` 을 **`-`** 로 쓴다.

| 입력 | 출력 |
|---|---|
| `null` | `k=-` |
| `""` | `k=-` |
| `"  "` | `k=-` |

### I5. sanitize 규칙
| 대상 | 제거/치환 |
|---|---|
| 키 | `[A-Za-z_][A-Za-z0-9_]*` 아니면 해당 쌍을 버리고 DEBUG 경고 |
| 값 | `\n` `\r` `\t` → `\n` `\r` `\t` (리터럴 2글자 이스케이프), 공백 → `_`, `\|` → `/` |
| 메시지 | `\n` `\r` `\t` → 리터럴 이스케이프. 공백·`\|` 는 허용 |

> 개행이 진짜 파서 킬러다. 공백보다 우선순위가 높다.

### I6. 마스킹은 **정확 키 매칭**
소문자로 정규화한 키가 민감 키 **집합에 속할 때만** 마스킹.
`contains` 부분일치 금지 — `auth` 가 `authType` 을 가리는 게 기획서 §9-2 의 교훈이다.
마스킹된 값도 여전히 공백 없는 토큰이어야 한다 → `***`.

기본 집합:
`password, passwd, pwd, token, access_token, refresh_token, id_token, jwt, secret,
 apikey, api_key, authorization, auth_header, cookie, session_id, ssn, rrn,
 phone, tel, mobile, email, mail, card, card_no, pin`

## 5. 정규식 (뷰어 구현 기준)

`PREFIX` 는 `re.escape` 적용 후 삽입.

```python
BODY = re.compile(
    r'^evt=(?P<event>[^\s|]+)'
    r'(?P<fields>(?:\s+[A-Za-z_][A-Za-z0-9_]*=[^\s|]+)*)'
    r'(?:\s+\|\s?(?P<msg>.*))?$'
)
TAG  = re.compile(r'^' + re.escape(prefix) + r'_(?P<domain>[A-Z0-9_]+)$')
```

접두사 3종은 `viewer/loglens/parser.py` 의 `_PREFIX_PATTERNS` 참조.

## 6. 정규화된 레코드 (파서 출력)

```jsonc
{
  "kind":   "structured" | "unstructured" | "raw",
  "ts":     "08-12 11:23:45.678",   // 소스가 준 그대로, 없으면 null
  "level":  "I",
  "tag":    "APP_AUTH",
  "domain": "AUTH",                 // structured 만
  "event":  "LOGIN_OK",             // structured 만
  "fields": { "uid": "123" },
  "msg":    "로그인 성공",
  "pid":    1234,
  "tid":    5678,
  "payload": null,                  // 원문 묶음의 머리 줄이면 요약 (8절). 아니면 null
  "raw":    "<받은 한 줄>"
}
```

`raw` 는 항상 채운다. 뷰어가 어떤 레코드든 받은 줄을 보여줄 수 있어야 한다.
(원문 묶음의 머리 줄만 예외로, 본문을 뗀 머리만 남긴다. 본문은 따로 모아 둔다 — 8절.)

## 7. 왕복 검증 (round-trip)

손으로 쓴 픽스처는 양쪽에 같은 실수를 심을 수 있다. 그래서 진짜 검증은:

```
Java Formatter --생성--> 한 줄 --> Python Parser --> 필드 비교
```

`lib/core` 의 `Formatter` 가 뽑은 줄을 `viewer` 파서가 되읽어 필드가 일치하는지 본다.
`make roundtrip` 참조.

## 8. 원문 (payload) — 요청·응답 본문을 통째로

서버에서 받은 JSON·XML 을 그대로 봐야 할 때 쓴다. 일반 레코드로는 못 한다: 한 줄 한도에서 잘리고(I2),
메시지 정리가 줄바꿈을 `\n` 두 글자로 바꾸면서 원래 있던 `\n` 과 구분할 수 없게 만든다(I5).

```
evt=ADDR_ADD_RES_BODY flowId=a1 plId=k31 plPart=1 plParts=2 plBytes=5120 | {"result":"ok","list":[...
evt=ADDR_ADD_RES_BODY flowId=a1 plId=k31 plPart=2 plParts=2 plBytes=5120 | ...]}
```

레벨은 항상 `D`. 태그(도메인)는 호출부가 준 그대로다 — 원문 전용 도메인은 두지 않는다.
어떤 레코드가 원문 조각인지는 **예약 필드가 말해 준다.**

### 8.1 예약 필드

`pl` 뒤에 대문자가 오는 이름은 라이브러리가 쓴다. 호출부는 이 이름을 필드로 쓸 수 없다 (`place` 는 된다).

| 필드 | 뜻 | 언제 |
|---|---|---|
| `plId` | 묶음 id. 프로세스마다 다른 두 글자 + 36진 순번. 뷰어는 logcat 의 pid 와 묶어 키로 쓴다 | 모든 조각 |
| `plPart` | 몇 번째 조각인가 (1부터) | 모든 조각 |
| `plParts` | 전체 조각 수 | 모든 조각 |
| `plBytes` | **실린 본문**의 UTF-8 바이트 수 (가린 뒤, 이스케이프 전). 뷰어가 되살린 본문과 대조한다 | 모든 조각 |
| `plCut` | 상한을 넘어 뒤를 버렸을 때, **원래 본문**의 UTF-8 바이트 수 | 버렸을 때만 |
| `plErr` | 본문을 싣지 못한 이유. `mask` = 가리기 실패, `excluded` = 세션 파일로 내보낼 때 뺌 | 그럴 때만 |

호출부가 넘긴 필드(`flowId` 등)와 예약 필드는 **조각마다 전부 반복한다.** 첫 조각이 유실돼도
나머지가 어느 흐름의 무엇인지 스스로 말할 수 있어야 한다. 호출부 필드는 일반 레코드와 같은 규칙으로
정리하고 가린다(I5, I6). `msg` 는 줄 수 없다 — 그 자리에 본문이 들어간다.

### 8.2 본문 이스케이프

본문은 `| ` 뒤(메시지 자리)에 싣는다. 읽을 수 있는 글자 그대로 두고, 되돌릴 수 없게 만드는 것만 바꾼다.

| 원래 글자 | 실리는 모양 | 비고 |
|---|---|---|
| `\` | `\\` | **가장 먼저.** 이게 없으면 JSON 안의 `\n` 과 진짜 줄바꿈이 섞인다 |
| 줄바꿈, CR, 탭 | `\n` `\r` `\t` | |
| 그 밖의 제어문자, U+2028, U+2029, 짝 없는 서로게이트 | `\uXXXX` | 버리지 않는다. U+2028/9 는 줄을 가르는 글자라 세션 파일을 다시 열 때 줄이 쪼개진다 |
| 조각 **맨 앞·맨 뒤**의 스페이스 | `\s` | 파서가 줄 끝 공백을 떼어 낸다(I3). 안쪽 공백은 그대로 |
| 조각 맨 앞·맨 뒤의 다른 공백(NBSP 등) | `\uXXXX` | 같은 이유 |
| 조각이 `...[cut]` 으로 끝날 때 마지막 `]` | `\u005D` | 잘린 줄(I2)로 보이지 않게 |
| 안쪽 공백, `\|` | 그대로 | 메시지 자리는 둘 다 허용한다 |

뷰어는 조각마다 이스케이프를 되돌린 뒤 순서대로 붙인다. 모르는 이스케이프(`\q`)는 그대로 둔다(I3).

### 8.3 불변식

**P1. 조각은 각자 온전한 레코드다 (I1 유지).** 줄 전체가 한도(I2) 이하가 되게 나눠 담으므로
원문 줄에는 `...[cut]` 이 붙지 않는다. 조각 크기는 계약이 아니다 — 머리 길이에 따라 달라지고,
뷰어는 크기를 가정하지 않는다. 나누는 자리는 글자 경계이고, 이스케이프가 두 조각에 걸치지 않는다.

**P2. 빠진 조각은 숨기지 않는다.** logcat 은 줄을 잃을 수 있다. 뷰어는 받은 조각만 이어 붙이되
어느 조각이 없는지 그 자리에 표시하고, 구조(JSON·XML)로 읽지 않는다. 다 받았는데 `plBytes` 와
되살린 크기가 다르면 그것도 알린다.

**P3. 원문은 릴리스에서 나가지 않는다.** 릴리스 정책(`ReleasePolicy`)을 무엇으로 골랐든,
출력 대상이 런타임으로 켜 달라고 하든 열리지 않는다. 받겠다고 밝힌 출력 대상에만 간다
(logcat 은 받고, 파일은 기본으로 받지 않는다).

**P4. 가리기는 자르기보다 먼저.** 본문 안에서 민감 키(I6 의 집합, 정확 일치)의 값을 `***` 로 바꾼 뒤에
상한을 적용한다. 먼저 자르면 닫는 따옴표가 사라진 값이 가려지지 않은 채 남는다. 가리다 실패하면
본문을 싣지 않고 `plErr=mask` 를 남긴다.

가리는 모양: JSON 의 `"키": 값`(값이 객체·배열이면 통째로), 문자열 안에 한 번 더 싸인 JSON 의
`\"키\": \"값\"`, XML 의 `<키>값</키>` 와 `키="값"`, 주소·폼의 `키=값`. 이건 **안전망**이다.
키 이름으로 드러나지 않는 개인정보(메모 본문 등)는 가려지지 않는다. 그래서 로그인·토큰·인증 응답은
원문으로도 싣지 않는다.

**P5. 상한.** 한 번에 싣는 본문은 기본 64KB(UTF-8)까지다. 넘으면 뒤를 버리고 `plCut` 에 원래 크기를
적는다. `plBytes` 는 실린 만큼이다.

### 8.4 뷰어가 하는 일 (구현 기준)

- 조각을 **받는 즉시** 따로 모은다 (`viewer/loglens/payloads.py`). 로그 버퍼에는 묶음마다 한 줄(머리)만
  남기고, 그 줄에서 본문과 예약 필드를 뗀다. 그래서 통계·이슈 규칙·흐름·이벤트 사전이 조각 수만큼
  부풀지 않고, 본문 속 글자가 이슈 규칙에 걸리지 않는다
- 같은 `plId` 라도 pid 가 다르면 다른 묶음이다. 조각 수나 크기가 다르게 다시 오면 새 묶음으로 본다
- 숫자가 이상한 조각(순번이 범위 밖 등)은 원문으로 치지 않고 보통 레코드로 둔다
- 세션 파일로 내보낼 때 본문은 기본으로 뺀다. 뺀 자리는 `plErr=excluded` 한 줄로 남긴다
- 본문을 JSON·XML 로 풀어 보여 줄 때 값을 바꾸지 않는다 (큰 정수를 숫자로 읽지 않는다)

### 8.5 왕복 검증

`make roundtrip` 의 PAYLOAD 케이스가 이 절을 지킨다. Kotlin 이 만든 조각 줄들을 뷰어의 조립 경로에
그대로 넣어, 되살린 본문이 입력과 글자 하나 다르지 않은지 본다 (한글·이모지 경계, 한 줄에 딱 맞는
크기, 공백에서 갈리는 경우, 줄을 가르는 글자, 본문 안 민감 키, 상한 초과).
