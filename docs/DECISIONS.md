# 구현 결정 기록

[기획서](../기획서.md)는 설계 의도를 담는다. 이 문서는 **그걸 실제로 만들면서
초안과 달라진 것 / 초안이 말하지 않아 내가 정한 것**만 기록한다.
기획서를 고쳐 쓰지 않고 따로 두는 이유는, 초안이 무엇을 예측했고 무엇을 놓쳤는지가
그 자체로 기록할 가치가 있어서다.

---

## D1. 초안의 파서 정규식은 틀렸다 — 접두사와 본문을 분리

**초안:**
```
^(?:(?<time>\d{4}-\d\d-\d\d ...) )?(?<level>[VDIWE])/<PREFIX>_(?<domain>[A-Z]+)...
```

**문제:** `\d{4}-\d\d-\d\d` 는 연도를 요구하는데, `adb logcat` 의 표준 포맷들
(`brief`, `time`, `threadtime`)은 **연도를 찍지 않는다**. 초안의 `time` 그룹은
사실 파일 싱크의 포맷이다 — 그건 우리가 소유하니까 연도가 있는 게 맞다.
두 소스의 접두사를 하나의 옵셔널 그룹으로 합치려 한 게 실수였다.

**결정:** 얇은 **접두사 파서 3종**(threadtime / brief·time / filesink) + 공용
**본문 파서 1개**. 접두사는 소스마다 다르고, 계약인 것은 본문뿐이다.

**부수 효과:** adb 호출 시 `-v threadtime` 을 **명시적으로 고정**한다. 포맷을
사용자 환경 기본값에 맡기면 파서가 조용히 깨진다.

## D2. 도메인 문자 집합을 넓혔다

초안의 `[A-Z]+` 는 `FILE_XFER`, `API2` 같은 지극히 평범한 도메인을 거부한다.
→ `[A-Z0-9_]+`.

## D3. `<PREFIX>` 는 config 에서 오므로 정규식 이스케이프

초안은 `<PREFIX>` 를 정규식에 그대로 끼워 넣었다. prefix 는 사용자 config 값이라
정규식 메타문자가 들어올 수 있다. `re.escape` 후 삽입한다. (테스트 있음)

## D4. 빈 값 센티널 `-`

초안의 문법에서 값은 `\S+` 라 `k=` 는 매치되지 않는다. 그런데 `null`/`""` 을
넘기는 call site 는 반드시 생긴다. 그 한 번에 레코드 전체가 강등되면 안 되므로
emitter 가 `-` 로 바꾼다.

## D5. 잘림은 UTF-8 **코드포인트 경계**에서

초안은 "4KB 근처 잘림 대비, 초과분은 통째로 자르고 `...[cut]`" 까지만 말한다.
한글은 UTF-8 3바이트, 이모지는 4바이트(서로게이트 페어)다. 바이트로 자르면
문자가 반으로 갈려 mojibake 나 디코딩 실패가 난다. `Truncator` 는 바이트로 세고
코드포인트로 자른다. (한글·이모지 각각 여러 한도에서 테스트)

## D6. 개행이 공백보다 위험하다

초안은 "값에 공백/구분자 없음"만 말한다. 실제 파서 킬러는 **개행**이다 —
한 줄 = 한 레코드가 깨지면 그 뒤가 전부 어긋난다. `Sanitizer` 는 값과 메시지
**양쪽에서** `\n`/`\r`/`\t` 를 리터럴 이스케이프로 바꾼다. 공백·`|` 는 값에서만 잡는다.

## D7. 파서는 관용적, emitter 는 엄격 — 줄 끝 공백

**실제로 당한 버그.** 합성 생성기가 필드 뒤에 공백 한 칸을 남겼고, 그것 때문에
`UPLOAD_DONE` 레코드가 전부 unstructured 로 강등돼서 대시보드의 FILE_XFER
성공률이 **0%** 로 나왔다. 로그는 멀쩡해 보였고 숫자만 틀렸다 — 제일 나쁜 종류의 버그다.

두 군데를 고쳤다: 생성기(원인)와 파서(`body.rstrip()`, 방어).
공백 한 칸에 레코드를 버릴 이유가 없다.

## D8. 릴리스 게이팅 기본값은 "디버그 아님"

`LogLens.init()` 을 부르기 전 `debug = false`. 초기화를 잊었을 때 V/D 가
**새는** 것보다 **조용히 빠지는** 쪽이 안전하다. 안전한 방향으로 실패한다.

## D9. core 를 순수 자바로 (Kotlin 아님)

기획서 §10 은 "Kotlin 우선"을 로드맵에 뒀고, §5 의 인터페이스 예시는 자바였다.
core 를 안드로이드·서드파티 무의존 순수 자바로 두면:

- 일반 JVM 에서 `javac` 만으로 컴파일·테스트된다 (JUnit 조차 없이)
- **뷰어 파서와의 왕복 검증**을 실제로 돌릴 수 있다 ← 이게 결정적이었다
- `minSdk 21`, 자바 앱에서도 그대로 쓰인다

Kotlin DSL 은 core 위에 얹는 얇은 레이어로 남겨둔다 (로드맵).

## D10. 이슈 규칙은 예외 **클래스명이 있는 줄만** 잡는다

처음 규칙(`"FATAL EXCEPTION|Exception|Error"`)은 크래시 하나를 이슈 여러 개로
쪼갰다: `FATAL EXCEPTION: main` 줄이 `UnknownCrash` 로, 실제 예외 줄이
`IllegalStateException` 으로 따로 잡혔다. 이슈 트레이의 존재 이유가 "그룹핑"인데
그걸 스스로 어긴 셈이다.

→ `[\w.$]+(?:Exception|Error)\b` — 클래스명처럼 생긴 토큰이 있는 줄만.
(회귀 테스트 있음: 헤더나 `at ...` 프레임이 별도 이슈로 새면 실패한다)

## D11. 퍼널은 flowId 가 있으면 흐름 단위, 없으면 카운트 근사

기획서 §9-5 가 "상관 ID 는 초기에 결정"이라고 경고한 그 지점이다. 뷰어는
`flowId` 필드가 있으면 흐름 단위로 이탈률을 내고, 없으면 단순 카운트로 근사한
뒤 **어느 모드인지 UI 에 표시한다**. 근사값을 정확한 값인 척하지 않는다.

## D12. 규칙 `when` 의 속성은 화이트리스트

config 의 이슈 규칙이 임의 속성명을 검사하면 오타가 조용히 "매치 안 됨"이 된다.
허용 속성 목록을 두고, 벗어나면 **로딩 시점에 예외**를 던진다. 조용한 실패보다 낫다.

## D13. 뷰어는 표준 라이브러리만 쓴다

의존성 0. 이유: `pip install` 없이 파일 복사만으로도 돌고, PyInstaller 단일
바이너리 패키징이 쉬워지고, 사내 네트워크 제약이 있는 환경에서도 붙는다.
SSE 서버는 `http.server.ThreadingHTTPServer` 로 충분하다.

## D14. 소스를 추상화했다 (adb / file / synth)

초안은 adb 만 상정한다. 소스를 인터페이스 뒤로 빼면:

- **기기 없이** 뷰어 전체를 개발·테스트·데모할 수 있다 (`--source synth`)
- 로드맵의 `.session` 저장/재생이 붙을 이음매가 이미 생긴다 (`--source file`)
- 재연결 로직이 adb 소스 안에 갇힌다 — 상위 레이어는 끊김을 몰라도 된다

## D15. SSE 는 헤더보다 먼저 구독한다

원래 순서는 `헤더 전송 → subscribe()` 였다. 그러면 클라이언트가 헤더를 받은 시점과
서버 쪽 구독이 성립하는 시점 사이에 들어온 레코드를 **조용히 놓친다**. 브라우저는
아무 에러도 못 보고 그냥 몇 줄이 비는데, 사람 눈으로는 절대 안 잡힌다.
API 테스트를 쓰다가 이 경합에 걸려서 발견했다. → `subscribe()` 를 헤더보다 앞으로.
